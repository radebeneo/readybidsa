# Supabase dev project setup

Use a **separate development project**. Never point local development at production data.

## 1. Create the project

1. Sign in at <https://supabase.com/dashboard> and create a new project (the free plan is
   enough for development). Choose a region close to South Africa if one is offered.
2. Save the database password in your password manager.

Creating a project is free on the free plan. Check the plan before confirming so nothing is
billed unexpectedly.

## 2. Apply the schema

Pick one option.

**Option A: SQL editor (no tools needed)**

1. Open **SQL Editor** in the dashboard.
2. Paste the contents of `supabase/migrations/20261028000000_initial_schema.sql` and run it.

**Option B: Supabase CLI**

```powershell
pnpm dlx supabase login
pnpm dlx supabase link --project-ref <your-project-ref>
pnpm dlx supabase db push
```

The migration creates:

- **Nine organisation-scoped tables:** `organisations`, `organisation_members`, `tenders`,
  `documents`, `source_segments`, `analysis_runs`, `processing_jobs`, `requirements` and
  `requirement_sources`. Every row carries its `organisation_id`, and composite foreign keys
  stop a row from pointing at another organisation's data.
- **Read-only row level security.** Signed-in members can only `SELECT` rows of organisations
  they belong to (`is_org_member`). There are no insert, update or delete policies. All writes
  go through the API.
- **A `documents_immutable` trigger** so a stored document version cannot change after
  upload: its organisation, tender, storage path, SHA-256 hash, version number, size and page
  count are fixed. A re-upload creates a new row with the next version.
- **A private storage bucket `documents`:** PDF only, 15 MB limit. Objects live at
  `<organisation id>/<tender id>/<document id>.pdf`, with paths generated by the server.
  Members can read objects only under their own `<organisation id>/` folder. Uploads and
  deletes go through the API, and the browser only receives short-lived signed URLs issued
  after a permission check.

If you raise the bucket's file size limit, raise `MAX_UPLOAD_BYTES` to match, never above it.

## 3. Configure Auth

ReadyBid uses email and password sign-in.

1. **Authentication > Sign In / Providers:** make sure **Email** is enabled.
2. **Authentication > URL Configuration:**
   - **Site URL:** `http://localhost:3000`
   - **Redirect URLs:** add `http://localhost:3000/tenders` (sign-up confirmation links return
     there).
3. **Confirm email:** with this on, new users must click the emailed link before signing in.
   Supabase's built-in email sender is rate-limited and meant for testing only. For a dev
   project you can either keep it on and use real inboxes, or turn it off to sign in
   immediately.

Tokens are verified by the API against the project's signing keys (JWKS), so no extra setting
is needed. Set `SUPABASE_JWT_SECRET` only if the project still signs tokens with the legacy
HS256 secret.

## 4. Configure ReadyBid

From **Project Settings > API** (or **API Keys**), copy the values.

Root `.env` (API and worker):

```dotenv
SUPABASE_URL=https://<your-project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service role key>
SUPABASE_STORAGE_BUCKET=documents
```

`apps/web/.env.local` (browser, sign-in only):

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://<your-project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon / publishable key>
```

The service role key bypasses row level security. Keep it in the API and worker only. Never
put it in `apps/web` or any `NEXT_PUBLIC_*` variable. The anon key is public by design; the
read-only policies above are what protect the data.

Restart the API and restart (or rebuild) the web app. The dashboard's Supabase row should
change to "Configured".

## 5. Check it

- **Table Editor:** the nine tables exist and each shows "RLS enabled".
- **Storage:** the `documents` bucket exists, is not public and allows only `application/pdf`.
- **Isolation:** sign up two users in separate browsers. Each creates an organisation and a
  tender. Neither should see the other's tenders, documents or requirements. This check has
  not been run yet; record the result in `docs/implementation-status.md`.
